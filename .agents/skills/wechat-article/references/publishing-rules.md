# Publishing rules

- The CLI and deterministic renderer own production HTML; do not hand-author HTML or CSS.
- The first visible article-body module is one natural paragraph introducing the project and topic, with no “项目引子” or “项目因子” label, `wx-hero` title card, English kicker or article directory. Keep the WeChat platform title and the separately uploaded cover.
- The article directory must contain the complete H2/H3 outline. Titles have no leading bullet; numbering is natural, never `01` or `01.1`.
- Code fences must render as dark code cards. Images must fit a 390px mobile screenshot.
- QA must inspect each illustration in context, its source and units, and whether it helps answer the reader's question. Reject decorative generic flowcharts that substitute for explanation and visible analysis-version framing even when the underlying facts are traceable.
- A dedicated cover, successful deterministic QA, successful independent QA, unchanged working-copy hash, and WeChat preflight are required before any draft mutation. Independent visual QA must run on a vision-capable model proven by the per-run screenshot preflight; a model that cannot read the screenshots must not be used for QA. Mechanical template-row deletion (`--remove-toc-filler`) may use the deterministic diff gate without a model pass.
- Body images are uploaded and rewritten to remote URLs in `publish/article.md`; do not publish local file paths.
- Create and update are separate actions. Updating always requires an explicit `media_id`.
- Approval binds article, image, cover, layout and rendered HTML fingerprints. Any change invalidates review. Scoped revisions additionally lock all text and assets outside their declared scope.
- Re-fetch an update target before uploads and immediately before mutation. Reject changed remote content or a mismatched target; preserve author, source-link and comment settings. If the remote draft drifted only in markup shape while visible text is unchanged (for example the WeChat editor re-saved it) and the user replaced the cover, re-baseline the revision target and preserve the remote cover (`preserveRemoteThumb`) instead of re-uploading the local one; any visible-text change still blocks and requires human reconciliation.
- Readback compares complete visible text and image source/width/height. Preview URLs come from that fresh response. Persist pending, queued and visibly opened separately; queued is not visible completion.
- After each completed article or revision reaches the verified draft stage, automatically open the target article's latest real draft page in the current task's Codex right-side browser panel using `open_in_codex` with `placement: "right"` and `target: { type: "browser", url: verifiedDraftUrl }`; no separate opening confirmation is needed. Do not use an external browser or merely return a link. Use the fresh readback URL, including `response.news_item[0].url`, and verify it belongs to the intended article and `media_id`. Do not substitute an older draft for unsynchronized local changes. If a URL is unavailable or opening is blocked, report that limitation and do not invent links or bypass restrictions.
